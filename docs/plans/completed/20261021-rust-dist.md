# rust-dist: release archives without a Makefile target

Done: 2026-10-21

Every Rust repo carries a near-identical `make dist` (build per target, cargo-cross for Linux and Windows, tar/zip with readme and LICENSE). rust-build should do it from a list of targets, so repos drop the target; `dist` stays for special cases (wavo's dSYM).

- [x] `rust-dist` (JS): `targets` (Apple ones with cargo on a Mac, the rest with cargo-cross 1.6.0, glibc 2.28, toolchains in ~/.cache/cargo-cross), the root package's binaries from cargo metadata, `<name>-dev-<target>.tar.gz` (`.zip` for Windows) with readme and LICENSE into target/distrib.
- [x] rust-build: `targets` input calling `$/rust-dist`, caching ~/.cache/cargo-cross; `dist` kept.
- [x] test.yml: a binary fixture built for the runner's target and a cross target; archives' contents checked; an Apple target refused off macOS.
- [x] readme; v1 moved with the person's approval.
- [x] unjar and clankr PRs on `targets`, their `dist` targets removed.

## Result

`v1` at 60ac7e6. CI builds a binary fixture for Apple natively and Linux through cargo-cross, and refuses an Apple target off macOS. Through `@v1`: unjar built its macOS archive (`unjar -V` 0.1.0-4-g01c07ad) and clankr four (macOS, Linux x86_64/aarch64, Windows) with no Makefile target. wavo, macmon and cctrail keep `dist: make dist`.
